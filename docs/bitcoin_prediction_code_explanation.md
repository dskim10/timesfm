# TimesFM 비트코인 예측 코드 설명 및 분석

이 문서는 `bitcoin_prediction_advanced_timesfm3.ipynb` 노트북 코드 중 주요 구현 방식과 개념에 대해 지금까지 나눈 질의응답을 정리한 문서입니다.

## 1. 백테스팅을 위한 데이터 전처리 및 롤링 윈도우 생성

시계열 예측 모델(TimesFM 등)을 평가하기 위해 비트코인 데이터를 수집하고 전처리하여 롤링 윈도우(Rolling Window) 형태의 데이터셋으로 변환하는 과정입니다.

* **데이터 수집 및 추출**: `yfinance`를 사용해 60일치 5분 단위(`interval="5m"`) BTC-USD 데이터를 가져옵니다.
* **파생 변수(Feature Engineering)**: 예측 성능을 높이기 위해 종가를 바탕으로 이동평균선(SMA, 1시간)과 상대강도지수(RSI, 14-period)를 계산합니다.
* **데이터 정리**: 이동평균과 RSI 계산으로 인해 발생한 앞부분의 결측치(NaN) 구간을 제외(`dropna()`)하고 유효한 인덱스(`valid_idx`)만 남깁니다.
* **롤링 윈도우 및 정규화(Data Leakage 방지)**: 
  * 모델이 과거 512 스텝(`context_len`)을 보고 미래 1 스텝(`horizon_len`)을 예측하는 백테스트를 총 288번(`eval_len`, 24시간) 수행하도록 데이터를 분할합니다.
  * 이때 매우 중요한 점은 전체 데이터가 아닌 **매 윈도우(잘라낸 512개 과거 데이터) 안에서만 정규화(`fit_transform`)를 수행**한다는 것입니다. 이를 통해 모델이 미래 데이터를 미리 훔쳐보는 '데이터 누수(Data Leakage)'를 방지합니다.

## 2. `fit_transform`과 데이터 누수 방지

`fit_transform`은 Scikit-Learn에서 데이터를 전처리할 때 쓰이는 함수로, 두 가지 작업을 한 번에 수행합니다.

1. **`fit()`**: 넘겨받은 데이터의 통계치(예: 평균, 표준편차)를 계산하여 기억합니다.
2. **`transform()`**: 계산된 통계치를 바탕으로 데이터를 변환(표준화)합니다. 즉, 평균을 0, 표준편차를 1로 맞춥니다.

**이 코드에서 중요한 이유**: 
만약 전체 60일치 데이터에 한 번에 `fit`을 적용해버리면, 과거 데이터를 정규화할 때 '미래의 가격 정보(미래의 평균과 분산)'가 섞이게 됩니다 (미래 참조 편향). 따라서 반복문 안에서 잘라낸 512개의 과거 데이터에만 매번 `fit_transform`을 적용해야 모델이 오직 과거 정보만으로 공정하게 평가(백테스팅)받을 수 있습니다.

## 3. `predict_batch` 함수 인자 설명

`predict_batch`는 여러 개의 시계열 데이터(배치)를 한꺼번에 입력받아 미래를 예측할 때 사용하는 TimesFM의 핵심 함수입니다. 주요 인자는 다음과 같습니다.

* **필수 인자**
  * `contexts` (`list[np.ndarray]`): 예측의 기준이 되는 과거 메인 시계열 데이터 리스트. (예: 과거 비트코인 종가)
  * `horizon` (`int`): 과거 데이터를 바탕으로 미래 몇 스텝을 예측할 것인지 지정. (예: 1)
* **보조 변수 (Covariates)**
  * `past_only_covariates`: 거래량, SMA, RSI처럼 과거까지만 알 수 있는 보조 변수. `contexts`와 길이가 같아야 함.
  * `past_future_covariates`: 요일, 공휴일처럼 미래 시점의 값도 미리 알 수 있는 보조 변수. `contexts + horizon` 길이를 가짐.
* **결과 제어 및 후처리**
  * `return_quantiles` (`bool`): `True`로 설정 시 단순 점 예측뿐만 아니라, 예측의 불확실성을 나타내는 10개의 분위수(Quantiles)를 함께 반환.
  * `sort_quantiles` (`bool`): 분위수 역전 현상을 막기 위해 예측된 분위수를 오름차순 정렬.
  * `make_positive` (`bool`): 모든 예측값을 0 이상으로 클리핑(음수 방지).
* **모델 전처리 옵션**
  * `use_znorm` (`bool`): 모델 내부적으로 Z-score 정규화를 수행한 뒤 다시 복원해서 반환.
  * `padding_mode`: 데이터 길이가 요구사항보다 짧을 때 빈자리를 채우는 방식.

## 4. `point_forecasts`, `p10_forecasts`, `p90_forecasts`의 차이

모델이 뱉어내는 결과물은 '점 예측'과 '범위(분위수) 예측'으로 나뉩니다.

* **`point_forecasts` (점 예측)**: `res.forecast[0]`
  * 모델이 생각하는 **가장 확률이 높은 단 하나의 예측값**입니다. (예: "내일 가격은 $65,000")
* **`p10_forecasts` (10 백분위수 예측 - 비관적 하한선)**: `res.quantiles[0, 0]`
  * 예측 분포 중 **하위 10%**에 해당하는 값. 실제 가격이 이보다 떨어질 확률은 10%밖에 안 된다는 뜻의 신뢰 구간 하한선입니다.
* **`p90_forecasts` (90 백분위수 예측 - 낙관적 상한선)**: `res.quantiles[0, -1]`
  * 예측 분포 중 **상위 90%**에 해당하는 값. 실제 가격이 이보다 올라갈 확률은 10%밖에 안 된다는 뜻의 신뢰 구간 상한선입니다.

이들을 함께 사용하면 단일 예측값뿐만 아니라, "적어도 P10에서 P90 사이(80% 신뢰 구간)에서 움직일 것이다"라는 **불확실성을 고려한 안정적인 시나리오**를 만들 수 있습니다.
